## Что означает оставшийся вывод npm audit

После обновлений обычный `npm audit` всё ещё перечисляет **19 high-записей**, но все они относятся к **одному** предупреждению [GHSA-fc5q-39xc-vjpf в picomatch](https://github.com/advisories/GHSA-fc5q-39xc-vjpf). Это библиотека сопоставления путей, которую используют несколько инструментов. На момент проверки опубликованной исправленной версии нет. Число записей включает зависимые пакеты, а не 19 независимых ошибок сайта.

Для известного вектора добавлена локальная защита в `scripts/patch-dependencies.mjs`: опасное повторение одной wildcard-ветви получает существующий безопасный literal fallback парсера. Она применяется к трём установленным копиям picomatch при `postinstall`, до упаковки standalone. Контрольные суммы исходных файлов закреплены; неожиданная версия или чужое изменение приводят к отказу установки, а не к молчаливому пропуску. Сложные опасные extglob-шаблоны намеренно трактуются буквально; обычные шаблоны проекта и простые повторяющиеся группы проверены тестами.

Версии пакетов и метаданные уязвимостей не подменяются, поэтому стандартный сканер продолжает показывать исходное предупреждение. `npm run audit:dependencies` допускает только этот конкретный advisory после проверки патча и тестов известных шаблонов с ограничением времени. Любой новый advisory приводит к ошибке команды. Нельзя считать весь стандартный `npm audit` «нулевым».

После выхода официального исправления нужно обновить соответствующие зависимости, удалить локальную защиту и её исключение из проверяющей команды, повторить `npm run check` и `npm run audit:dependencies`. Установку с `--ignore-scripts` применять нельзя: она пропустит `postinstall`; проверочные команды обнаружат отсутствие защиты.

Обновлены Vinext `1.4.6`, Vite `8.3.8`, React / React DOM / React Server DOM Webpack `19.3.1`, Cloudflare Vite Plugin `1.70.0`, Wrangler `4.164.0`, Drizzle Kit `0.31.11`, связанные типы и lock-файл. Для fflate закреплена исправленная `0.7.5`, для старого вложенного esbuild загрузчика миграций — `0.25.12`. Существующая фиксация Sharp `0.35.5` сохранена.

## Миграция и дальнейшая проверка перед выпуском

Добавлена `0005_track_client_limit.sql`: nullable `track_request.client_key` и индекс по нему и времени. В поле хранится хеш, а не исходный IP. Существующие записи сохраняются; старый код по-прежнему может вставлять заявки. Старые миграции не изменялись. Новую миграцию нужно применить **до** старта новой версии; без неё healthcheck вернёт 503. На production она не применялась.

`Dockerfile` теперь включает полный ESLint, тесты зависимостей и сервера, TypeScript, сборку и HTTP-проверку standalone. Локальный Docker Engine недоступен; проверка полного Linux Docker build выполнена в GitHub Actions, результаты приведены ниже. Установка пока также сообщает о deprecated `@esbuild-kit/*`, которые использует актуальный Drizzle Kit; уязвимый вложенный esbuild заменён проверенным override. Сборщик выдаёт диагностические предупреждения upstream-плагинов о sourcemap и совместном static/dynamic import; они не являются ошибками сборки и не скрывались.

Добавлен workflow `Verify Linux container` для `dev`. После сборки он запускает образ с read-only корнем, UID 1000, сброшенными capabilities, `no-new-privileges`, ограничением процессов/памяти/CPU и отдельной tmpfs-базой. Проверяются миграции, healthcheck, SSR, ассеты, отправка и безопасный повтор сообщения через HTTPS-заголовки прокси, а также права 0700/0600. Такой же контроль добавлен в production workflow **до** передачи образа на сервер. Тестовые записи существуют только в отдельном временном контейнере.

Команды для повторения:

```sh
npm run install:ci
npm run check
npm run audit:dependencies
docker build --tag cdek-fm:local-audit .
```

Серверная проверка только на чтение: контейнер сайта healthy, `PRAGMA quick_check` — `ok`, нарушений внешних ключей нет; `nginx -t` успешен, Certbot timer активен, заголовки IP и авторизации на прокси обработаны ожидаемым образом. Есть две резервные копии перед выкладками, свободно около 62,5 ГБ. Регулярное внешнее резервирование по-прежнему требует настройки. Системные `fwupd`, `fwupd-refresh` и `quotaon` отмечены failed; к выполненным проверкам приложения они не относятся и не изменялись.

Визуальное оформление остаётся прежним. Заметка фронтенду: проверить понятность переключателя 3D, чтобы остановленную пользователем анимацию не принимали за поломку фона. Изменений CSS и новых визуальных решений нет.
