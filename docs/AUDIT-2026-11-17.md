Проверены API, SQLite и миграции, сессии редакции, публикация настроек, чат и вложения, модерация, заявки на песни, обращения в поддержку, доставка и CSV-отчёты. Изменения предназначены для `dev`. Исходники интерфейса, `master`, production и настройки доступа не менялись.

## Исправленные ошибки

| Проблема | Воспроизведение | Исправление |
| --- | --- | --- |

Отсутствующая таблица или колонка даёт 503; полностью мигрированная пустая база — 200. |
| Исключения базы выходили из обработчиков API, хотя клиенты ожидают JSON. | Принудительный отказ `DB.prepare` приводил к отклонению вызова обработчика вместо ответа API. | Для чата, картинок, настроек, заявок на песни, модерации и отчёта добавлена общая обработка исключений с JSON и HTTP 503. Ответы не содержат деталей базы или секретов. Ошибки уже начавшейся потоковой CSV-передачи не могут изменить отправленный HTTP-статус. |
| Большая CSV-выгрузка могла повторять строки при поступлении новых данных. | Между страницами добавлена новая песня: выгрузка 450 существовавших заявок возвращала 451 строку. | Вместо `OFFSET` используются курсоры: время и ID заявки, день активности или стабильный ключ участника. Колонки CSV и защита от формул сохранены. Участники теперь перечисляются по стабильному ключу, а не по времени последнего сообщения. Выгрузка остаётся потоковой: это не транзакционный снимок на один момент времени, значения ещё не прочитанных строк могут изменяться.

В `app/cinematic/support-dialog.tsx` стоит воспроизвести сценарий «отправить на медленной сети → закрыть окно до ответа → открыть снова». Закрытие сбрасывает номер заявки, но поздний ответ снова его устанавливает. Для нового открытия нужно явно определить ожидаемое поведение и обработку незавершённого запроса, сохранив ID отправки для безопасного повтора. На бэкенде идемпотентность проверена; этот сценарий интерфейса отмечен по коду, без браузерного воспроизведения.

Для переключателя 3D полезно проверить понятность состояний «включено / выключено»: ранее статичный фон у пользователя объяснялся состоянием этой кнопки, а не отказом сервера. Визуальное решение остаётся за разработчиком фронтенда.
