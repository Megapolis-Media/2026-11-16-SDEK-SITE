# Шаблон веб-проекта Megapolis Media

Стартовый репозиторий для командной разработки сайтов, в том числе с AI-ассистентами. Код приложения и технология сборки выбираются отдельно.

## Ветки

- `dev` — единая рабочая ветка команды и ветка по умолчанию. `megapolisbroadcasting`, `Knyazzer` и владелец `Megapolis-Media` работают прямо в ней: pull → изменения → проверки → commit → повторная синхронизация → push в ту же `dev`. Для команды личные ветки и PR в `dev` не нужны.
- `master` — версия для production. Слияние только через PR аккаунтом владельца `Megapolis-Media`. Workflow выкладки ожидает подтверждения этого аккаунта в environment `production`.
- `<github-login>` — постоянная ветка внешнего участника без прямого доступа в `dev`. Он работает в fork и присылает PR. Уже существующие личные ветки команды автоматически не удаляются; новые задачи команда выполняет в `dev`.

В `master` запрещён прямой push. В обеих ветках запрещены удаление и force push, включая аккаунты с правом прямой записи в `dev`. Работайте под своим аккаунтом. Право прямого push в `dev` также есть у владельца `Megapolis-Media`.

## Начало работы

Читайте [CONTRIBUTING.md](CONTRIBUTING.md). AI-ассистент обязан прочитать [AGENTS.md](AGENTS.md).

Публичный репозиторий доступен для чтения всем. Без прямого доступа участник работает в fork и присылает PR. Команда получает Write, без прав администратора; приглашение нужно принять. Право прямого push в `dev` проверяется по текущим Rulesets: обычного Write или непринятого приглашения недостаточно. Перед каждой задачей и каждым push нужно получить свежую `dev` и сохранить изменения других разработчиков.

Для владельца: [создание проектов и администрирование](docs/MAINTAINERS.md).

В Git отправляем исходники и готовые ассеты сайта. Секреты, тестовые картинки, брейншторминг, промежуточные генерации и AI-артефакты остаются локально в игнорируемых каталогах. Подробный порядок — в CONTRIBUTING.md и AGENTS.md.
